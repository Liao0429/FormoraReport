# FormoraReport 决策记录

> 所有关键决策在此记录，附理由与证据。

## D-001 主技术栈：Python 3.14+（CI 固定 3.14，与开发机一致；3.12+ 兼容）+ PySide6
- **日期**：2026-10-22
- **决策**：采用 Python + PySide6 作为唯一主技术栈。
- **理由**：文档处理生态最强（调研 15 库中 13 个是 Python 宽松许可库）；本机零额外 SDK；离线优先；PyInstaller 可打包独立 EXE；许可证组合支持开源与可商用。
- **证据**：`reports/RESEARCH_REPORT.md` 第三、四节。
- **备选否决**：C#/.NET（未装 SDK，Open XML 生态较弱）；Tauri（未装 Rust，生态较新）。

## D-002 核心文档库：python-docx + docxtpl
- **决策**：DOCX 模板解析与保真填写用 `python-docx` + `docxtpl`。
- **理由**：docxtpl 正是「原 Word 模板占位符替换 + 保留格式/表格/图片」机制，MIT/LGPL-2.1 商用友好。
- **证据**：调研项目 1、2。

## D-003 PDF 提取：pdfplumber；OCR 可选 PaddleOCR
- **决策**：PDF 文本/表格提取用 pdfplumber（MIT）；扫描件/截图 OCR 用 PaddleOCR（Apache-2.0）作为**可选增强，默认不加载**。
- **理由**：避免 PyMuPDF 的 AGPL 义务；PaddleOCR 中文/版面/表格最强且可离线。

## D-004 无 AI 模式为默认启动模式
- **决策**：应用默认进入无 AI 模式，核心业务（解析/映射/填充/图表/导出）完全不依赖网络与模型。
- **理由**：满足「断网/无密钥仍可用」的硬性验收。

## D-005 AI 模式采用用户自配的 OpenAI 兼容 API
- **决策**：AI 增强模式仅由用户主动启用，用户自配 base_url/model/key；密钥加密存本地；不上传用户文档除非用户明确操作；生成内容必须可逐项审核。
- **理由**：避免厂商锁定、尊重隐私、符合验收「AI 不得捏造数据」。

## D-006 MVP 范围（P4 第一里程碑）
- **决策**：MVP = 导入模板(DOCX) → 导入数据(CSV/XLSX/TXT) → 自动识别占位符 → 字段映射 → 预览 → 生成 DOCX → 校验输出。随后补模板管理、批量、历史、基础 UI 动效。
- **理由**：任务书要求「优先交付真正可用的无 AI 模式」。

## D-007 PDF 导出策略
- **决策**：优先尝试本地 LibreOffice 无头转换或 Word COM；两者都无则只导出 DOCX 并明确提示，不虚假宣称。
- **理由**：诚实边界，避免未经验证的 PDF 保真。

## D-008 禁止事项（持续约束）
- 不把 AGPL（如 PyMuPDF）作为核心依赖。
- 不把用户实验报告、API 密钥、日志隐私、机器特定路径提交到仓库。
- 不虚构测试结果、性能数据、构建成功状态。
- 遇到许可证风险/数据外传/破坏性操作/付费服务，先与项目负责人确认。
