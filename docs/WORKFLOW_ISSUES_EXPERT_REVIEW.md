# FormoraReport 高频使用场景 · 工作流问题清单与修复建议

> 视角：实验报告高频使用场景专家（真实用户工作流）
> 依据：全源码阅读 + 样例实际运行验证（`.venv` 可用，docx 已装）
> 范围：6 大高频场景；每条含 现象 / 根因(代码位置) / 影响 / 修复建议
> 版本基准：2.2.0

---

## 场景 1：不同学校/老师模板差异大（合并单元格、页眉页脚、表格嵌占位符、图片占位）

**P1 · 1.1 页眉/页脚里的表格占位符扫描不到**
- 现象：很多学校把「姓名/学号/班级/日期」放在**页眉的表格**里，页脚放学校名/页码占位。这些字段完全检测不到，生成后页眉留空。
- 根因：`template_parser.py:114-119` 只遍历 `section.header.paragraphs` / `footer.paragraphs`，不扫描页眉页脚内的表格（python-docx 的 `header.paragraphs` 不含表格）。
- 修复：递归遍历 `header._element` / `footer._element` 内所有 `w:tbl` 单元格文本，一并提取 `{{ }}`；更稳妥的是统一遍历 `doc.element.body.iter()` 全部 `w:t` 文本节点（含嵌套表格、文本框）。

**P1 · 1.2 嵌套表格中的占位符扫描不到**
- 现象：实验数据表常套在单元格里（表格套表格）。`doc.tables` 只返回**顶层表格**，python-docx 不暴露嵌套表，`doc.paragraphs` 也不含单元格段落 → 占位符漏检，生成后原样留下 `{{...}}`。
- 根因：`template_parser.py:89-111` 只遍历 `doc.paragraphs` + `doc.tables`。
- 修复：对每个 cell 递归遍历其 `_tc.tables` 和 `_tc.paragraphs`；或用 `lxml` 遍历 body 全部 `w:t` 做占位符检测。

**P1 · 1.3 合并单元格解析错误**
- 现象：表头跨列/跨行合并（如「实验结果」横跨两列）时，`row.cells` 对合并区域返回**重复的同一 Cell 引用**，导致 `header`/`sample` 文本重复、列数虚高；跨行合并会让表头行错位。
- 根因：`template_parser.py:96-104` 直接用 `row.cells`。
- 修复：按 XML 真实单元格去重（`row._tr.tc_lst`），识别 `gridSpan` / `vMerge` 合并跨度，还原逻辑行列后再提取表头与占位符。

**P2 · 1.4 图片占位无法锚定到指定段落/位置**
- 现象：模板常用一段说明文字（如「实验结果图：」）后留空位，而不是 `{{chart}}` 占位符。当前只有字段名含「图表/截图」关键字才注入图片；普通文字处无法精确插入图片。
- 根因：图片只能通过 `{{占位符}}` 用 `InlineImage` 替换（`generator.py:16-28`）。
- 修复：支持「图片定位占位」——解析时记录含图片锚点的段落，允许把图片插入到指定段落（docxtpl 的 RichText/子文档或段落后插入）。

**P2 · 1.5 占位符写法不统一（`${姓名}`、`【姓名】`、`<姓名>`）**
- 现象：不同老师模板用 `{{ }}`、`${ }`、`【 】` 等，当前只认 `{{ }}`（docxtpl 也只支持它），其余写法一律不识别 → 整份报告空白。
- 修复：解析阶段检测到其他占位符风格时，提示并可一键转换为 `{{ }}`；或解析器兼容 `${{ }}` 并在导入页说明。

## 场景 2：批量生成几十上百份（不同学生不同数据）

**P0 · 2.1 行切换不刷新「值」列（已运行确认）**
- 现象：`row_combo` 切换数据行时界面「值」永远是第 1 行。点「生成」结果虽正确（`_current_row()` 取当前选中行），但用户预览看到的是错行数据，极易误判。
- 根因：`mapping_page.py:95-151` 创建了 `row_combo`，但**没有连接 `currentIndexChanged`** 到 `_sync_row_combo`（仅有 type_combo/col_combo 有连接，见 174/181 行）。
- 修复：`self.row_combo.currentIndexChanged.connect(lambda _: self._sync_row_combo())`，并在数据列字段值旁显示当前行标签。

**P0 · 2.2 数据模型只支持「一行 = 一份报告」，不支持「一个学生 = 多行」**
- 现象：真实实验数据常是长表（姓名,时间,温度，每学生多行）。当前 `generate_batch` 按行生成，张三有 3 行就产出 3 份独立报告，而不是把张三多行聚合成一份。
- 根因：`report_service.py:229` `for i, row in enumerate(data.rows)` 逐行生成。
- 修复：增加「分组字段」配置（如姓名/学号），批量时按列分组，每组渲染一份，循环块注入该组所有行。

**P0 · 2.3 批量报告全部复用同一张图表**
- 现象：`collect_image_vars` 在循环外只生成**一次**图表（用全表数据），100 个学生每份都插同一张「全班图」，学生本人数据不对。
- 根因：`report_service.py:222-225` 在 `for` 循环外调用 `auto_chart(state)`；`auto_chart` 用 `state.data.rows` 全表（78-109 行）。
- 修复：批量时按当前行/分组重新生成该学生自己的图表；若图意是全局数据，在 UI 明确「图表基于全部数据」并允许关闭。

**P1 · 2.4 单份与批量循环语义不一致**
- 现象：单份生成 `resolve_context` 注入 `data_rows = state.data.rows`（**全部行**）；批量只注入 `[row]`。同一「实验数据」循环块，单份输出全表、批量输出 1 行，用户难以理解。
- 根因：`report_service.py:69` vs `:236`。
- 修复：统一语义——单份当前行也只注入当前行（或当前学生分组行），UI 明确「这份报告的数据范围」。

**P1 · 2.5 图片字段无法按学生区分**
- 现象：图片绑定是任务级全局（一个 `image_vars`），做不到「张三插张三截图、李四插李四截图」。批量时所有学生图片相同。
- 根因：`FieldMapping` 的 image 类型是全局值，无按行概念。
- 修复：允许图片字段映射到「图片路径列」，批量时每行取该列值作为图片路径。

**P1 · 2.6 输出文件名「第 N 行」无法对应到人**
- 现象：`report_service.py:237` `第{i+1}行.docx`，100 份分不清谁是谁，无法按学号排序提交。
- 修复：支持「文件名字段」配置，默认用姓名/学号列值命名，重名再追加序号。

**P1 · 2.7 批量结果无集中式打开/PDF 入口**
- 现象：批量完成只设 `last_batch_dir`，生成页仍显示上一次单份的 `output_path`，用户要自己进文件夹找；也没有「批量转 PDF」。
- 修复：批量完成后在生成页展示批次目录、成功/失败明细，并提供「打开批次文件夹」「批量导出 PDF」按钮。

## 场景 3：实验数据多种形态（多列数值、时间序列、百分比、文本数字）

**P0 · 3.1 百分比/文本数字列无法自动出图（已运行确认）**
- 现象：`转化率` 列存 `85%` 或 `"12.5"` 字符串时，`isinstance(v,(int,float))` 判 False → 不生成图表。CSV 中 pandas 可能已把 `"12.5"` 转 float，但 `"85%"` 一定是字符串。
- 根因：`report_service.py:83-88` 数值检测只看 Python 类型。
- 修复：数值检测先 `pd.to_numeric` / `float()` 尝试转换，能转成功算数值列；百分比列图上显示 `%`。

**P0 · 3.2 时间序列的轴选择完全错误（已运行确认）**
- 现象：对 `时间(s), 温度(℃)`，`auto_chart` 选 y=时间、x=温度，图是反的。
- 根因：`report_service.py:90-92` 取 `numeric_cols[0]` 作 y、第一个非 y 列作 x。
- 修复：轴启发式——首列为时间/日期/序号类（列名含 时间/日期/序号/时刻/s/min）作 x 轴；否则首列 x、其余数值列各作一条 y 序列。并在图表字段上提供 x/y 下拉框让用户手选。

**P1 · 3.3 多列数值只能画第一条**
- 现象：`通道A/通道B` 多系列只画第一个数值列。
- 根因：`chart.py:35-58` 只支持单 y 序列折线/柱状。
- 修复：支持多系列折线图（每列一条线 + 图例），至少允许用户选多列 y。

**P1 · 3.4 数据格式不经处理直接进报告**
- 现象：`mapper.resolve_values` 一律 `str(v)`（`mapper.py:78`）。浮点 `85.0` 输出 `85.0`、日期输出 `2026-10-25 00:00:00`、科学计数法 `1e-05`，报告难看。
- 修复：按列类型格式化——整数去 `.0`、百分比加 `%`、日期格式化为 `YYYY-MM-DD`；支持自定义小数位。

**P2 · 3.5 空值/NaN 处理**
- 现象：`df.where(df.notna(), None)` 把 NaN 转 None，`resolve_values` 输出 `""`；图表里 NaN 会断线，且 `auto_chart` 对含 None 的列直接不算数值列，缺一两个值的整列不出图。
- 修复：图表数据用 `dropna` 而非整列判空；报告对 None 提供「缺省显示 —」选项。

## 场景 4：模板里有循环表格但字段没对上

**P0 · 4.1 循环体内字段被当成顶层占位符（已运行确认）**
- 现象：`{% for row in data_rows %}{{ row['项目'] }}` 中，`row['项目']` 和 `row['数值']` 被 `_PLACEHOLDER_RE` 捕获进入顶层 `placeholders`，自动映射变成两个「常量」字段，映射表出现 `row['项目']`、`row['数值']` 这类怪字段，用户困惑。
- 根因：`template_parser.py:15` 的正则在全文扫描，未区分循环上下文（82 行对循环块内文本也 `findall`）。
- 修复：解析时区分「顶层占位符」与「循环体内字段」——对 `{% for %}` 块内的 `{{ }}` 不再加入顶层映射，只在导入页展示「循环块：实验数据(data_rows)，内字段：项目,数值」。

**P0 · 4.2 循环变量名必须是 `data_rows` 才能自动注入**
- 现象：`resolve_context` 硬编码注入 `data_rows`（`report_service.py:69,236`）。模板写 `{% for s in students %}` 或 `{% for item in items %}` 时该变量 undefined，循环静默为空，不报错。
- 修复：解析循环块时记录变量名，注入时给每个循环块变量都注入同一份数据（别名）；或做模板规范校验并警告不支持的循环名。

**P0 · 4.3 循环内引用的字段与数据列不匹配无提示**
- 现象：模板写 `{{ row['项目'] }}`，数据列叫「名称」。渲染时 `row['项目']` undefined → 表格该列空白，无警告。
- 修复：解析循环体内字段名，用 `auto_map` 别名做映射建议；校验时对「循环体引用了不存在的列」给出 error 级提示。

**P2 · 4.4 循环块识别正则太窄**
- 现象：`_LOOP_RE`（`template_parser.py:16`）只识别 `{% for x in y %}`，`\w+` 不支持中文变量名（`{% for 行 in 数据 %}` 识别不到）。
- 修复：正则放宽到 `[\w\u4e00-\u9fff]+`，兼容换行/空格。

## 场景 5：图表选择哪些列做 x/y 轴更合理

**P0 · 5.1 轴选择启发式缺失/错误（已运行确认）**
- 现象：时间/序号列应作 x、度量列应作 y；当前取第一个数值列作 y、第一个非数值列作 x，时间序列和多系列全部画反。
- 根因：`report_service.py:90-92`；`chart.py:35-58` 无轴语义。
- 修复：见 3.2——实现轴启发式 + 让用户可改 x/y/图表类型/标题/坐标轴标签。

**P1 · 5.2 图表类型固定为折线，柱状图 API 从未自动使用**
- 现象：`auto_chart` 只调 `generate_line_chart`。
- 修复：按数据特点选型（类别型 x → 柱状，连续/时间 x → 折线），或提供下拉选择。

**P1 · 5.3 图表标题/轴标签固定不可定制**
- 现象：标题固定 `"{y_col} 数据图"`，x/y 标签就是列名，无法改成「时间(s)」「温度(℃)」或加图例。
- 修复：图表字段支持配置标题、x/y 轴标签、图例、是否显示网格。

**P2 · 5.4 中文字体/清晰度/尺寸问题**
- 现象：`_FONT_CANDIDATES` 依赖本机中文字体（`chart.py:18`），打包到无中文字体机器会变方块；PNG 固定 dpi 150、宽 6.4in，插入 Word 固定 14cm，可能模糊或撑破版面。
- 修复：字体探测失败给提示；图表宽度按模板占位区域自适应；提供 dpi/尺寸选项。

## 场景 6：生成后要导出 PDF 提交、要打印

**P0 · 6.1 只能单份导出 PDF，无法批量转 PDF**
- 现象：`generate_page.py:78-88` / `preview_page.py:126-136` 的「导出 PDF」只处理 `state.output_path` 单个文件。批量几十份后必须逐个打开、逐个导出。
- 修复：提供「批量导出 PDF」——把批次目录所有 docx 转 pdf（复用 `pdf_exporter._lo_lock` 串行锁），输出到同目录，或可选合并为一个 PDF 供统一提交。

**P1 · 6.2 预览看不到图片/排版，无法判断能否提交**
- 现象：`preview_page.py:106-124` 只读段落与表格文本，图片不显示。用户看不出图表是否插入、是否撑破页面、页眉页脚是否正确。
- 修复：预览改为「所见即所得」——用 LibreOffice/Word 把 docx 转 PDF 再以 PDF 预览（QTextDocument 或嵌入 PDF 视图），或至少显示图片缩略图。

**P1 · 6.3 PDF 转换依赖外部组件且渲染可能与 Word 不一致**
- 现象：PDF 依赖本机 LibreOffice 或 Word COM，两者皆无则报错（诚实边界，但真实用户常卡在这）；LibreOffice 对合并单元格、嵌入图片、中文默认字体的渲染与 Word 有差异，打印/提交时版式可能变化（图表截断、行高变化）。
- 修复：两引擎都可用时优先 Word COM（更接近老师用 Word 查看效果）；导出后提示「建议用 Word 打开核对版式」。

**P2 · 6.4 打印/分页无控制**
- 现象：数据量不同导致分页位置不同，长表格可能跨页断开，打印时难看。
- 修复：提供分页预览；模板解析时支持「表格行不分页」（`cantSplit`）保留并提示。

**P1 · 6.5 提交命名规范（学号_姓名_实验报告.pdf）无法满足**
- 现象：批量文件名「第 N 行」不利于按学号排序提交；老师要求统一命名时只能手动改。
- 修复：与 2.6 合并，支持「命名模板」，批量导出 PDF 沿用该命名。
